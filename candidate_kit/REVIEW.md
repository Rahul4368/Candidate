# REVIEW.md

| # | Where | What is wrong | How to notice | Fix |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses `replace()` on the punch-in date and mishandles overnight shifts after midnight; it also relies on truncation/float conversion implicitly. | For a 22:00–06:00 shift, punch in at 02:00 IST should be compared with the prior day's 22:00 shift start. | Normalize timestamps to UTC whole seconds and compute against the correct attendance-day shift start. |
| 2 | `compute_overtime` | Always places shift end on `date_str`, so overnight shifts compare punch-out to the wrong day. | 22:00–06:00 shift punching out at 06:40 next day yields no overtime or a negative delta. | Move the shift end to the following calendar day for overnight shifts; only count overtime at 30+ whole minutes. |
| 3 | `compute_work_hours` | Python `round()` uses ties-to-even and binary floats, contrary to half-up rounding. | Durations landing exactly on a half-cent boundary can differ from the contract. | Use `Decimal` with `ROUND_HALF_UP`. |
| 4 | `create_employee` | Duplicate checking is check-then-insert and can race; `created_at` is naive local time. | Parallel creates with the same `emp_code` can both pass the check. | Enforce a unique index, catch `DuplicateKeyError`, and store UTC-aware timestamps. |
| 5 | `list_employees` | `skip = page * page_size` skips page 1's first page, and `total` ignores the department filter. | Page 1 starts after the first 20 records; filtered total doesn't match filtered results. | Use `(page - 1) * page_size` and count with the same filter. |
| 6 | `punch_in` | Doesn't return 404 for unknown employee before dereferencing `emp`; timestamps use local naive time and seconds instead of milliseconds can be accepted. | Unknown `emp_code` raises 500; timezone depends on host; epoch values are interpreted incorrectly. | Validate employee, validate epoch milliseconds, truncate to seconds and store UTC. |
| 7 | `punch_in` | Check-then-insert is not concurrency-safe and status isn't constrained. | Two parallel punch-ins can both succeed; `ABSENT` could be punched in. | Unique compound index on `(emp_code, date)` and validate presence-only statuses. |
| 8 | `punch_in` | Attendance date is derived from host-local date, not IST or overnight shift rules. | A UTC/IST boundary or overnight shift gets assigned to the wrong date. | Calculate attendance date in IST, accounting for overnight shifts. |
| 9 | `list_attendance` | Loads the entire matching collection into Python and sorts/slices in memory. | Performance and memory degrade on 100k+ rows. | Count with the filter and use indexed database sort/skip/limit. |
| 10 | `list_attendance` | Pagination, filter validation, and ordering are incomplete; internal `_id` leaks while timestamp values are BSON datetimes. | Invalid date ranges are accepted and output differs from the API contract. | Validate date/status inputs, sort by date descending then code ascending, and serialize instants as epoch milliseconds. |
| 11 | Missing punch-out endpoint | No rule enforcement for selecting the most recent open record, elapsed-time bounds, or concurrent requests. | Overnight punch-outs fail or two simultaneous requests both update the record. | Atomically update only records with `punch_out: null`, validate timestamps, and return the required status codes. |
| 12 | Missing regularization endpoint | No correction validation or audit trail. | Corrections cannot be made, or changes cannot be reconstructed. | Recompute derived fields and append one immutable `history` entry containing only changed fields. |
| 13 | Missing analytics endpoints | No monthly, department, leaderboard, or trend analytics. | Contract endpoints return 404. | Implement aggregation-backed endpoints and ranking/window logic. |
| 14 | Missing explain endpoint and indexes | No execution-plan endpoint or indexes for the workload. | Explain requests fail; list/report queries may use collection scans. | Create indexes idempotently at startup and expose explain output. |
| 15 | `/health` | Always returns healthy without pinging MongoDB. | API reports ready while the database is down. | Ping MongoDB and return 503 on failure. |

**Reviewed and retained:** The employee business key is `emp_code`, not MongoDB `_id`; the two-collection model and stored derived analytics fields are retained. `ABSENT` and `LEAVE` are not punch-in statuses, and manual correction history must not be written by normal punch events.
